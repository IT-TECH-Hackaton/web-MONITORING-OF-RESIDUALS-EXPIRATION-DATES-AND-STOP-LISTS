# Мониторинг остатков, сроков и стоп-листа

Система для смены ресторана: сколько продуктов на складе, когда они истекают, какие блюда не продаём и что лучше предложить гостю. Это не касса и не экран тикетов кухни.

ТЗ: учёт движения продуктов, контроль количества и сроков годности, стоп-лист, рекомендации по приоритетной продаже.

## Что значит 86

**86** (произносится «eighty-six», «заэкстить») — ресторанный жаргон из США: блюдо **снято с продажи на смене**. «86 salmon» = лосося больше не берём, зал не предлагает, касса не пробивает.

В Toast это так и называется: **86 list**. Плитка блюда серая, в углу «0». Можно не обнулить, а поставить остаток порций: «крылышек 4» — это уже не стоп, а **мало** (low). Когда дойдёт до нуля, позиция сама становится 86.

По-русски это **стоп-лист**. 86 — не код ошибки и не номер стола, а статус «нет в продаже».

В этой системе:

| Статус | На плитке | Смысл |
|---|---|---|
| Ок | обычная плитка | Можно брать |
| Мало (low) | число порций, янтарь | Заготовка на исходе |
| Стоп (86) | серая + «0» | Нельзя добавить в заказ |
| Приоритет | медный бейдж | Шеф сказал предлагать сегодня |

## Как устроен живой ресторан

Заказ гостя не живёт в этом сайте. Он идёт по конвейеру людей и кассы.

1. **Гость** садится, смотрит меню. Официант уже видит 86: серые позиции не предлагает. Если шеф пометил приоритет — предлагает его.
2. **Официант** бьёт заказ в **кассу** (терминал в руке или стойка): стол, блюда, «без лука», отправка на кухню. Иногда сначала блокнот, потом та же касса. Отдельного «сайта для заметок» нет.
3. **Кухня** получает не фискальный чек гостя, а **тикет** на цех (гриль, холодный, бар) — принтер или экран KDS.
4. **Повар** готовит по тикету. Кассы и телефона у него нет. Готово: тикет на спицу / колокол / большая кнопка bump на KDS.
5. **Раздача** (су, экспедитор) собирает стол целиком и отдаёт раннеру или официанту.
6. **Гость** ест. Счёт и оплата снова на кассе зала.

Стоп в этой цепочке орёт голосом («86 лосось») и сразу жмётся на кассе, чтобы следующий официант не пробил. Заготовка кончилась — повар кричит су, су ставит 0 порций. Доготовили — су плюсует порции. Килограммы на складе при этом могут не измениться.

### Кто чем жмёт

| Кто | Что делает | Где |
|---|---|---|
| Официант | Заказ, видит стоп и приоритет | Касса / хендхелд |
| Повар | Готовит, закрывает тикет | KDS или бумага |
| Шеф / су | 86, лимит порций, + заготовки | Касса или наш экран смены |
| Кассир | Счёт гостя | Касса |
| Менеджер | Приход, склад, списания | Бэкофис / наша консоль |

Мы в этой цепочке только до шага 2 и фоном после отправки: можно ли взять блюдо, сколько порций заготовки, что предложить, списание сырья с партий. Тикеты, bump и «заказ готов» не строим.

Для хакатона мобилка официанта **подменяет кассу**: стол + блюда + списание склада. Это демо-контур, не вторая касса ресторана.

## Два счётчика

Их нельзя смешивать.

| | Склад | Порции на смене (заготовка) |
|---|---|---|
| Что | Лосось в кг, партии, срок годности | «Соуса хватит на 8 тарелок» |
| Кто меняет | Поставка +, заказ гостя − | Шеф / су |
| Кончилась заготовка | Сырьё ещё может быть | Шеф ставит 0 / 86 |
| Доготовили | Не приход на склад | Шеф жмёт **+ порций**, зал снова видит блюдо |

Автостоп по техкарте («помидоров не хватает → капрезе в стопе») — только **кандидат**. Зал закрывает человек. Иначе система стопит блюдо, которое на линии ещё есть, или наоборот продаёт то, чего на заготовке уже нет.

Списание сырья с партий идёт **FEFO**: сначала та партия, у которой срок кончается раньше. Просроченное система списывает сама статьёй «срок».

## Кто пользуется этим проектом

| Роль | Где | Зачем |
|---|---|---|
| Менеджер | веб | Сводка (86 и сроки), склад, поставки, рецепты, журнал заказов, аналитика списаний |
| Шеф / су | веб, экран «Смена» | Кандидаты в стоп, 86, +/− порций, приоритет, короткие партии, акт брака |
| Официант | мобилка | Не взять 86, предложить приоритет, оформить демо-заказ |
| Повар на линии | нигде | Готовит по тикетам кассы |

**Сводка менеджера.** Первый экран после входа: 86 (стоп и мало), приоритет продажи, партии на сутки, автосписание по сроку, прогноз «скоро в стопе». Стоп отсюда не ставят.

**Ход смены**

- Утро, менеджер: поставка с «годен до» → партии на складе. Рецепты уже заданы.
- Открытие, шеф: смотрит кандидатов, ставит 86 или «осталось N», подтверждает 2–4 блюда в приоритет.
- Сервис, официант: серые плитки не берёт, сверху «сегодня предлагать», заказ списывает сырьё и минусует порции шефа.
- Сервис, шеф: заготовка кончилась → 86; доготовили → + порций. Брак — акт с причиной, не поле на партии в пик.
- Закрытие, менеджер: что в стопе, что истекло, куда списали.

## Запуск для разработки

Не поднимай весь `docker-compose`: контейнер web занимает порт 5173, как Vite.

Нужны Docker, .NET 8 SDK, Node.js.

```powershell
docker compose up -d postgres
cd backend\src\Api
dotnet run
```

API: http://localhost:5080  
Swagger: http://localhost:5080/swagger

В другом терминале, из корня репо:

```powershell
npm install
npm run dev:web
```

Веб: http://localhost:5173 (в `apps/web/.env.development` уже `VITE_API_URL=http://localhost:5080`).

Мобилка официанта: `npm start -w @repo/mobile`, тот же API.

Демо-учётки (сидер при старте API):

| Логин | Пароль | Роль |
|---|---|---|
| `manager` | `manager123` | менеджер |
| `kitchen` | `kitchen123` | шеф / кухня |
| `waiter` | `waiter123` | официант, только мобилка |

Сборка всего стека: `docker compose up --build` — postgres, API на 5080, веб на 5173 как nginx, без горячей перезагрузки.
